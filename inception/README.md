# Inception

## Description

Inception is a system administration project from the 42 curriculum. The goal of the project is to build a small infrastructure using Docker and Docker Compose.

The infrastructure is composed of several Docker containers, each running a specific service. The services communicate through a dedicated Docker network and use persistent storage where necessary.

The project consists of three main services:

* **NGINX**: the only service exposed to the host. It handles HTTPS connections and forwards PHP requests to WordPress through FastCGI.
* **WordPress**: runs PHP-FPM and provides the WordPress website.
* **MariaDB**: stores the WordPress database.

The final architecture is:

```text
                         HTTPS :443
                             |
                             v
                      +-------------+
                      |    NGINX    |
                      |   SSL/TLS   |
                      +------+------+
                             |
                        FastCGI :9000
                             |
                             v
                      +-------------+
                      |  WordPress  |
                      |   PHP-FPM   |
                      +------+------+
                             |
                         MySQL :3306
                             |
                             v
                      +-------------+
                      |   MariaDB   |
                      +-------------+

              All services share the "inception" network
```

## Project Description

### Docker

Docker is a platform used to package applications and their dependencies into isolated containers.

In this project, each main service runs in its own container:

* NGINX
* WordPress with PHP-FPM
* MariaDB

Each service has its own Dockerfile. Docker Compose is used to build, create and manage all the containers together.

The containers use `debian:bookworm` as their base image. The required packages are installed inside each image.

The services communicate using Docker's internal DNS. For example, WordPress connects to MariaDB using the hostname `mariadb`, while NGINX connects to WordPress using the hostname `wordpress`.

### Services

#### NGINX

NGINX is the entry point of the infrastructure.

It:

* listens on port `443`;
* provides HTTPS using an SSL certificate;
* serves the WordPress files;
* forwards PHP requests to WordPress using FastCGI;
* is the only container exposing a port to the host.

The NGINX configuration contains:

```nginx
listen 443 ssl;
fastcgi_pass wordpress:9000;
```

The SSL certificate is generated by the NGINX entrypoint script when the container starts if it does not already exist.

#### WordPress

The WordPress container runs PHP-FPM.

At startup, the entrypoint script checks whether `wp-config.php` exists. If it does not exist, WordPress is downloaded from the official WordPress website and extracted into `/var/www/html`.

The script then creates `wp-config.php` from the WordPress sample configuration and configures:

* the database name;
* the database user;
* the database password;
* the MariaDB hostname.

PHP-FPM is configured to listen on port `9000`.

#### MariaDB

MariaDB is used as the database server for WordPress.

During the first initialization, the entrypoint script:

1. initializes the MariaDB data directory;
2. reads the root and WordPress database passwords from Docker Secrets;
3. starts MariaDB temporarily without networking;
4. creates the WordPress database;
5. creates the WordPress database user;
6. grants the required privileges;
7. shuts down the temporary server;
8. starts MariaDB normally.

MariaDB is configured with:

```text
bind-address = 0.0.0.0
```

This allows connections from the other containers on the Docker network.

## Design Choices

### Virtual Machines vs Docker

A virtual machine emulates a complete computer and normally requires a complete guest operating system for each virtual machine.

Docker containers share the host's kernel while keeping applications isolated.

| Virtual Machines                     | Docker                              |
| ------------------------------------ | ----------------------------------- |
| Virtualizes an entire machine        | Isolates applications in containers |
| Usually requires a complete guest OS | Shares the host kernel              |
| Higher resource consumption          | Lower resource consumption          |
| Usually slower to start              | Containers start quickly            |
| Strong isolation                     | Lightweight process isolation       |

Docker is appropriate for this project because each service can be isolated into its own container without requiring a separate operating system for every service.

### Secrets vs Environment Variables

Environment variables are useful for non-sensitive configuration values.

This project uses `.env` for values such as:

```text
DOMAIN_NAME
MYSQL_DATABASE
MYSQL_USER
```

Passwords are sensitive information, so they are not stored in `.env`.

Instead, Docker Secrets are used for:

* the MariaDB root password;
* the WordPress database password.

The secrets are mounted inside the containers under:

```text
/run/secrets/
```

The entrypoint scripts read these files when they need the passwords.

This separates normal configuration from sensitive credentials.

### Docker Network vs Host Network

A Docker bridge network provides isolated communication between containers.

The three services are connected to the `inception` network. Docker's internal DNS allows containers to communicate using service names such as:

```text
mariadb
wordpress
```

With host networking, containers would share the host's network stack.

The Docker network approach is preferable here because the services only need to communicate with each other and NGINX is the only service that needs to be accessible from the host.

The resulting communication is:

```text
Host
 |
 | HTTPS :443
 v
NGINX
 |
 | wordpress:9000
 v
WordPress
 |
 | mariadb:3306
 v
MariaDB
```

### Docker Volumes vs Bind Mounts

Docker volumes are managed by Docker and are useful for persistent application data.

This project uses a Docker volume for WordPress:

```text
wordpress_data -> /var/www/html
```

This allows the WordPress files to remain available even when the WordPress container is recreated.

MariaDB uses a bind mount through a Docker volume configuration:

```text
/home/idiaz-ca/data/database
```

which is mounted into:

```text
/var/lib/mysql
```

A bind mount gives direct control over the storage location on the host, while a normal Docker volume is managed by Docker.

This project uses the bind-mounted host directory for the database so that the MariaDB data is stored in the required host location.

## Instructions

### Requirements

The project requires:

* Docker
* Docker Compose
* A Linux environment or virtual machine capable of running Docker

### Configuration

The project uses a `.env` file located at:

```text
srcs/.env
```

The current configuration contains:

```text
DOMAIN_NAME=idiaz-ca.42.fr
MYSQL_DATABASE=wordpress
MYSQL_USER=wpuser
```

The database passwords are stored separately as Docker Secrets:

```text
secrets/db_root_password.txt
secrets/db_password.txt
```

### Build the Images

From the `srcs` directory:

```bash
cd ~/inception/srcs
docker-compose build
```

### Start the Infrastructure

```bash
docker-compose up -d
```

Check the running containers with:

```bash
docker-compose ps
```

The three services should be running:

```text
mariadb
wordpress
nginx
```

### Access WordPress

NGINX exposes HTTPS on port `443`.

Open the following address in a browser:

```text
https://idiaz-ca.42.fr
```

Because the project uses a self-signed certificate, the browser may display a security warning. The certificate can be accepted for local testing.

### Stop the Infrastructure

To stop and remove the containers without removing persistent data:

```bash
docker-compose down
```

To start the infrastructure again:

```bash
docker-compose up -d
```

The WordPress files and MariaDB data are preserved by the configured storage.

### Useful Commands

Check the status of the services:

```bash
docker-compose ps
```

Check the NGINX configuration:

```bash
docker exec nginx nginx -t
```

Inspect the Docker network:

```bash
docker network inspect srcs_inception
```

Inspect the persistent volumes:

```bash
docker volume ls
```

View container logs:

```bash
docker-compose logs
```
